# Project decisions

## Made

- **Name: Pakespec** (chosen on 2026-10-17). Free on PyPI, npm, crates.io and GitHub that day; domain and trademark were not checked. Alternatives considered: Wobbel (from "Wobbeln", German for sweeping), Sweepy. Avoid "LTDZ" in the name (it ties it to one model).
- **Stack: Rust, with egui for the interface** (decided 2026-10-17). Plots with `egui_plot` (mockup A) and a custom-drawn bench-instrument view (mockup C). Why: runs on Windows and Linux as one small binary per platform, builds in GitHub Actions, and every dependency is permissive. Serial port through `serial2` (BSD-2-Clause or Apache-2.0). The Python client from the research phase stays in `tools/ltdz_client.py` for quick manual checks.
- **Application requirements (2026-10-17):**
  - **Selectable visual styles.** The user picks how the spectrum screen looks. The first two are the flat `egui_plot` style (mockup A) and the bench-instrument style (mockup C); more styles will be added later. Architecture consequence: a style is a plug-in view over the same sweep data; the core and the data model know nothing about drawing.
  - **Screen content (decided 2026-10-17): only the spectrum.** No waterfall and no separate marker table. What stays is part of the plot itself: a parameter header (reference level, scale per division, averaging, sweep time), a footer (center frequency, point count, span), markers drawn on the plot with their frequency and level, and optional max hold and min hold traces. Markers read out inside the plot or in the header.
  - **Four styles, from mockups (decided 2026-10-17):** Bench (light lab-instrument convention: header, 10 × 8 grid with level labels, thin trace, footer), Classic (dark, fine grid, live trace plus max and min hold, cursor readout), Instrument (graticule, glowing trace, automatic peak markers) and Modern (flat, max-hold shading, peak frequency labels). Styles are layouts; colors come from themes and any style can use any theme. Ready-made presets pair them: Light bench, Dark, Phosphor, Modern. A new theme, Phosphor (green on black), is added for the Instrument style.
  - Plots are drawn with egui's painter (not `egui_plot`) so the four styles share one drawing layer and a fixed scale; `egui_plot` is no longer a dependency. Zoom and pan are not available yet.
  - The vertical scale shows dBm (raw values only if no calibration is available); it fits the data with a reference level and a step per division chosen from 1, 2, 5 × 10ⁿ, and only moves when the trace leaves the scale or uses less than 40 % of it.
  - **Front panel (decided 2026-10-17, level 1).** The screen has a bench-instrument layout: soft keys in a column at the right of the screen, a row of hard keys under it (FREQ, SPAN, AMPT, SWEEP, TRACE, MARKER, PEAK, SYSTEM) plus a Sweep/Stop key, a number keypad with GHz, MHz and kHz keys, and a knob that also answers to the mouse wheel. Each hard key opens a menu of soft keys. The plain controls bar remains as a compact mode (SYSTEM menu). Keys for things the board does not have (RBW, attenuator, gain) are not shown. Level 2, a realistic physical look of the panel (bezel, relief, LEDs), is not done.
  - **Themes.** Colors, fonts and sizes come from a theme the user can switch (at least dark and light), applied to every style. Styles read colors from the theme and never hard-code them.
  - **Translatable interface.** English and Portuguese first, more languages later. Source strings are English; translations live in catalog files separate from the code, so adding a language means adding a file. Language is chosen in the settings and defaults to the system language. Text must not be built by concatenating fragments, because word order differs between languages; use full messages with placeholders. The translation library must follow the permissive-license rule.
  - The choices (style, theme, language, port) are saved in a user settings file.
  - **Serial port selection.** The port name differs between machines (`/dev/ttyUSB0`, `COM3`, ...) and can change after replugging. The application lists the serial ports with their USB identity (vendor and product id), pre-selects the single port that matches the board's CH340 (`1a86:7523`) when there is exactly one, and always lets the user choose another port by hand. It remembers the last choice. Detection only suggests: the CH340 identity is shared by many unrelated devices, so nothing is written to a port the user did not select or confirm, and the first sweep (a few points) acts as the check that a board answers. Implemented without a dependency on `serialport` (MPL-2.0): Linux reads USB ids from sysfs (done); Windows reads them from the registry; other systems list ports without ids.
- **Exception to the permissive-license rule: egui's default fonts** (decided 2026-10-17, option 1 of three). The crate `epaint_default_fonts` ships font files under OFL-1.1 and the Ubuntu Font License. They are free licenses, but not permissive in the MIT sense: they require the license text to travel with the binary, and a modified font must stay under the same license. They place no conditions on the application code. Accepted for this one crate, recorded in `deny.toml`. Third-party license texts must be shipped with release binaries. `BSL-1.0` (Boost, used by `clipboard-win` and `error-code`) is permissive and was added to the allowlist.
- **Pipeline:** GitHub Actions (`.github/workflows/ci.yml`): Ubuntu and Windows matrix running format check, clippy, tests against the board simulator and a release build; a separate job runs `cargo-deny` with the license allowlist in `deny.toml`. Hardware tests are ignored by default and run by hand (`tests/hardware.rs`).
- **Requirements for the application:** runs on Windows and Linux, and builds and tests in a GitHub Actions pipeline (matrix of `ubuntu-latest` and `windows-latest`). The runners have no board, so tests need a board simulator; hardware tests stay manual (`tests/hardware.rs`, ignored by default).
- **Dependency licenses:** only libraries with permissive licenses (MIT, Apache-2.0, BSD, ISC, Zlib and similar). No GPL, LGPL, AGPL or MPL dependencies. The pipeline should enforce this with a license allowlist check (for Rust, `cargo-deny`). Consequences: PySide6 (LGPL) is out, which removes the Qt option; egui and egui_plot (MIT or Apache-2.0) are in; for the serial port prefer a permissive crate such as `serial2` over `serialport` (MPL-2.0), to be confirmed with `cargo-deny` when the dependencies are added.
- **Project license: MIT** (decided 2026-10-17). `LICENSE` in the repository root. It fits the dependency rule above: only permissive dependencies.
- **Built-in calibration (2026-10-17):** the application ships with a reference dBm scale taken from the reference board (5.30 counts/dB, 0 dB at 455.67 raw; `docs/calibration.md`), so it shows dBm from the first run. A `calibration.toml` overrides it. This replaces the earlier plan of showing raw values until a calibration exists.
- **First release scope (2026-10-17):** the application shows the spectrum, has the basic controls of an analyzer, and the generator works. Several markers, export and the rest come later (see `feature-spec.md`, milestones).
- **Integrations (done 2026-10-17):** (1) the application must be usable from the command line so that other programs can control it, and (2) an MCP server so that an LLM can control it. The core library stays independent of the screen so both are thin front ends; see `feature-spec.md`, section K.
- **Tests (2026-10-17):** three layers, described in `testing.md`: unit and integration tests with the board simulator, tests of the screens with egui's test harness, and hardware tests that are ignored by default.
- **Target platforms:** Linux and Windows (development happens on a dual-boot machine).
- **Repository language:** everything in the repository is in English (code, comments, docs, commit messages, and the source strings of the interface), because the project will be published on GitHub. Translations of the interface (for example Portuguese) are data files and are the only non-English content.
